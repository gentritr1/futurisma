# Ability state and replay contract

`src/game/polarity-simulation.js` owns deterministic ability state shared by Polarity and Tideline. Despite its `PolaritySimulation` class name, course-specific devices and launch strips come from an explicit configuration. `PolarityRuntime` and `TidelineRuntime` adapt this state to the existing game, renderer, sound and HUD. This is a tested local ability-state boundary; it is not a complete multiplayer simulation or a claim that the game is multiplayer ready.

The core has no DOM, audio, renderer, network, wall-clock or ambient-randomness dependency. Its input is a validated course configuration, an unsigned 32-bit seed and an ordered sequence of method calls. Given the same inputs and call ordering, it produces the same state and event identifiers.

`PowerCourseConfig` supplies a stable course/configuration ID, the gravity flag, ordered pickup anchors and kinds, optional alternate kinds and charge, launch strips, optional directed transfer windows, and stable field IDs. Polarity uses `polarity-abilities-v2`; Tideline uses `tideline-v1` with gravity disabled. Array order is part of the contract because snapshot arrays refer to pickup/window indices. The constructor validates the data, copies it and computes a 32-bit FNV-style fingerprint of its JSON serialization. Equivalent data serialized in a different property order need not have the same fingerprint. That fingerprint detects accidental configuration mismatch; it is not authentication, a cryptographic digest or tamper protection.

At the adapter boundary, `resolveAbilitySeed()` uses a valid explicit `?seed=<uint32>` when supplied, otherwise seed 714 for diagnostic runs, otherwise a browser cryptographic random uint32. Invalid explicit seeds fall back to 714. The core itself only accepts a supplied numeric seed and never generates randomness. A normal newly loaded session can vary its pattern; restarting the race retains its seed so the restart is comparable. A future room authority could distribute a common seed, but no room authority exists here yet.

Ability time advances at **120 integer ticks per second**. Runtime adapters accumulate elapsed time into whole ticks; rendering does not advance state. Pause makes no simulation call. Finish coast uses clock-only advancement, so existing effects settle without collecting new devices. Determinism requires replaying commands at the same tick and in the same order; arbitrary frame-dependent command timing is not made deterministic merely by sharing a seed.

| Core call | State transition |
| --- | --- |
| `step(progress, lateral, lap)` | Advances one tick, accepts the observed course position and checks forward pickup crossings. Lap may remain the same or advance by one; stale or skipped lap numbers fail. |
| `advanceTicks(count)` | Advances clocks without moving race progress or collecting devices. Accepts an integer count from 0 through 1200. |
| `requestFlip(progress, lateral, geometrySafe)` | Applies the directed window, lane, centre, cooldown and once-per-window/lap rules; requires the adapter's geometry check. Returns an accepted event or a denial reason. |
| `requestPower(progress)` | Activates the held device when no power is active and resolves a painted-strip launch bonus. Returns an accepted event or a denial reason. |
| `onShieldImpact(fieldId)` | Applies the timed shield reward once per configured field/lap. Returns a nitro-reserve refund between 0 and .18. |
| `recover(progress)` | Returns to the lower lane, ends the active effect and imposes a six-second transfer hold. Held inventory and collected/used history remain. |
| `reset(seed?)` | Starts fresh state. Omitting the argument retains the current seed. |
| `snapshot()` / `restore(value)` | Copies JSON-safe ability state or validates and atomically replaces it. An invalid restore throws without changing the existing state. |

Progress and lateral position still come from the existing vehicle simulation. `geometrySafe` and a shield field ID still come from local course checks. These are trusted adapter inputs, not an authorization boundary against a dishonest client. `step` rejects non-finite positions and lateral values beyond its sanity limit, but it does not verify vehicle speed, physical reachability or checkpoint completion. The core's current `state` record is publicly readable/mutable local state, not an immutable or secured server entity.

Snapshots carry schema version 1, configuration ID and fingerprint, seed, tick, lap, observed progress/lateral, lane and transfer clocks, held/active device kind and charge, active-effect clocks, per-lap pickup/window/field history, counters, upper-deck time and the latest event records. Restore validates the version/configuration identity, numeric ranges and finite positions, allowed lane/power values, active-clock relationships, array lengths and lap values, known field IDs, counter ranges, and event types/order/identifier shape. JSON round trips and continuation during both a transfer and an active power are covered by tests. The snapshot does not include vehicle velocity, full race/checkpoint state, rivals, rendering, audio or transport state.

Events have a monotonically increasing sequence, tick, lap, lane, type, related index, optional device kind, timing flag and refund. Types are `flip`, `pickup`, `power`, `absorb` and `recover`. IDs are `${configId}:${seedInHex}:${sequence}`. The state retains only the most recent 32 events; adapters consume each sequence once for sound, haptics and messages. Replaying the same race intentionally recreates the same IDs. Different live races with the same seed/configuration therefore require an external race/session ID before these IDs could serve as globally unique network identifiers. This bounded recent-event buffer is not a durable command log or a reliable network-delivery mechanism.

Power timing creates a visible skill reward. A full-charge Surge lasts three seconds, or four when activated in a painted launch strip. Charge scales the base duration as `3 × (.8 + .2 × charge)` seconds, rounded to 120 Hz ticks; Polarity upper-route charge .65 produces about 2.79 seconds before any launch bonus. Surge still needs thrust and respects the 140 m/s limit in the shared speed helper. A five-second shield absorbs a visible phase field; an impact within 144 ticks (1.2 seconds) of activation returns .18 reserve and adds two seconds, capped at seven seconds remaining. Later absorption returns .06. Each field pays once per lap. The game adapter adds the refund to the existing nitro reserve and clamps the result to one.

Fair variation uses readable, stable lap plans. Pickup anchors and phase fields do not move unpredictably. A seeded A/B supply pattern selects eligible alternate device kinds and remains fixed for the lap; the next lap uses the other pattern. The world renders those kinds and the HUD shows **SUPPLY A/B**. In Tideline, the lit current switches between the authored left/right lines according to seed and lap. Only riding the lit line inside its current ranges grants the 1.85× recharge multiplier. That current rule is pure course data outside the ability class; it is recomputable from the snapshot seed/lap and authored Tideline configuration, but its rules are not included in the ability configuration fingerprint. Polarity's demo chooses one seeded express route for the whole race to preserve its six-second deck commitment.

Real multiplayer would still require all of the following:

- An authoritative vehicle/race simulation, including acceleration, steering, collision, surface/flight behavior, checkpoints, lap progression, contact rewards and interactions between players. The authority must derive valid progress, lateral position, transfer geometry and shield impacts itself.
- A versioned room/race configuration that covers all shared physics, track geometry and course-specific rules, not only this ability fingerprint; a race/session identifier; authority-assigned seeds, starts and stable player identities.
- A transport and message schema for ordered/timestamped player input, acknowledgements, snapshots and events; duplicate, stale and out-of-order handling; bounded queues, rate limits, disconnect/reconnect and error handling.
- Client prediction and server reconciliation for vehicle and ability state, interpolation of other players, clock synchronization, and testing under latency, packet loss and jitter. Current runtime adapters do not yet expose an end-to-end network snapshot/reconciliation path.
- A lobby/session service with joining, leaving, ready/start coordination, race results and any chosen persistence or authentication model.

The current checks execute deterministic command traces under different tick groupings, compare continued JSON-restored state, reject incompatible or malformed snapshots atomically, verify forward/lateral pickup rules and lap guards, test skilled power timing, and exercise production input/runtime presentation on both courses. They provide evidence for this local ability contract only. There are no remote players, public network services, lobby, transport or multiplayer acceptance tests in this implementation.
